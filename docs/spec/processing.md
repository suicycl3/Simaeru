# 処理

## 購入履歴の同期

- サイトごとのアダプタ（`src/main/sites/*`）が、区画（`floor`）ごとに購入履歴を取得して `products` に書き込みます。対象はログインしているサイトの区画です。
- 差分同期（既定）: 購入日の新しい順に取得し、1 ページがすべて既知の作品になった時点で、その区画の取得を終えます。
- 全件同期: すべてのページを取得します。
- 区画ごとに成否を記録し、`sync_runs` に結果を残します（すべて成功 = `done`、一部失敗 = `partial`、中断 = `cancelled`）。
- 同期のあと、表紙のキャッシュの不足ぶんを取得し、紐付け候補を検出し直します。

## 作品の詳細の取得

作品の詳細（説明文・クリエイター・タグ・ダウンロード導線・ファイルサイズなど）は、1 作品ずつ取得します。

| 経路 | 条件 |
|---|---|
| 詳細を開いたとき（`library:detail`） | 取得済みなら保存済みの情報を返し、「再取得」のときだけ取り直す |
| 順次取得（`MetaCrawler`） | `meta_fetched_at IS NULL` ∧ `meta_attempts < 3` ∧ ログインしているサイトの作品を、設定の間隔と並列数で取得する |
| ダウンロードの直前 | 導線を取り直す（→ [ダウンロード](#ダウンロード)） |

順次取得は、設定がオフ・同期中・ログインしているサイトが無いときに止まります。失敗すると `meta_attempts` を 1 増やします。

| 速さ | 間隔（ミリ秒） | 並列数 |
|---|---|---|
| ひかえめ | 5000 | 1 |
| ゆっくり | 1000 | 1 |
| 標準（既定） | 500 | 2 |
| 速い | 300 | 4 |
| 最速 | 100 | 6 |

## ダウンロード

### キューに積む（`enqueue`）

作品ごとに次を行います。

1. 手元にファイルがあり、完了していない行が無い作品は積まない（ダウンロードし直しのときは積む）。
2. 手元にファイルが無いのに `done` の行が残っている作品は、その行を消す。
3. ダウンロード導線（`links` の `kind = 'download'`、または転送ページ）が無ければ詳細を取り直す（60 秒で打ち切り）。それでも無ければ、理由を入れた `error` の行を作る。
4. 導線ごとに行を作る（導線が複数なら `link_kind = 'split'`）。`done` の行は `done` のまま。FANZA 動画は画質違いのうち最も高い画質の導線だけを使う。
5. 積んだ行を「今回のまとまり」に加える。

DLsite の分割案内は詳細取得時に読み取り、対象作品のファイルリンクを番号順・重複なしで登録します。案内リンクは再取得用に残します。導線が見つかった場合、以前の「ダウンロード導線が見つかりません」のエラー行を消し、実ファイルの行に置き換えます。

ステータスバーの失敗件数は、画面に渡されたダウンロード行と後処理行のうち `state = 'error'` の合計です。管理パネルと同じ行を数え、同じ対象の後続ジョブがあっても過去の失敗行を除外しません。

### 実行

同時に実行する数は、`取得中 + 開始待ち + 準備中 < download.concurrency` の範囲です。空きがあると、`queued` の行を積んだ順に 1 行ずつ開始します。各行の開始は互いに独立しています。

```
queued ─開始─▶ （準備中）
  準備中:
    1. 保存先に完成したファイルがある / .part が全体の大きさに達している → 仕上げ
    2. 詳細を取り直してダウンロード URL を得る（60 秒で打ち切り、打ち切ったら保存済みの導線を使う）
    3. この間に一時停止・中止・削除された行は開始しない
    4. .part があれば続きから（90 秒以内に始まらなければ .part を消し、次回は最初から）
       無ければ、行専用の非表示ウィンドウで downloadURL（90 秒以内に始まらなければ失敗）
  ─開始─▶ running ─完了─▶ 仕上げ ─▶ done
                    ├─中止─▶ canceled
                    └─中断─▶ 失敗の扱い
```

- 開始したダウンロードは、開始したウィンドウで行と対応づけます。対応づけられないダウンロードは取り消します。
- 始まったダウンロードの MIME タイプが `text/html` なら、取り消して失敗にします（`attempts` を上限にして、自動ではやり直しません）。
- ダウンロード用ウィンドウの通信を見て、開始前に次のことが分かったら、90 秒を待たずに失敗にします（同じく自動ではやり直しません）。
  - http(s) 以外の URL へ転送された（アプリを起動するリンク）
  - `text/html` の応答が返り、3 秒たってもダウンロードが始まらない
  - 通信のエラー（`ERR_ABORTED` を除く）があり、3 秒たってもダウンロードが始まらない
- 失敗の理由には、URL のホストとパス（先頭 60 文字、クエリを除く）を入れます。
- 保存先: `download.root` の下にフォルダ構成（`download.template`）で決めたフォルダ。同名のファイルがあれば `名前 (2).拡張子` とします。保存中は `.part` を付けます。
- Windows のパス長に収まるよう、長いフォルダ名から短くします。
- 帯域制限は、すべてのダウンロードの合計が `download.maxBytesPerSec` を超えないよう、一時停止と再開で調整します。

### 仕上げ

1. `.part` を本来の名前にする（失敗したら `paused` にして理由を残す）。
2. 大きさが 0 または見つからなければ失敗の扱いにする（0 バイトのファイルは消す）。
3. `名前 (n).拡張子` で保存され、同じ作品の台帳に `名前.拡張子` があるときは、元をごみ箱へ入れて置き換える。
4. 行を `done` にし、台帳（`local_files`、`source = 'download'`）に登録する。
5. 作品の行がすべて終わっていれば、後処理を判断する（→ [後処理](#後処理)）。

### 失敗の扱い

`attempts` を 1 増やし、3 未満なら `queued`、3 以上なら `error` にします。再開は 1 秒後です。

### 見回り

20 秒ごとに、`running` なのに実行中・開始待ち・準備中・仕上げ中のどれでもない行を `queued` に戻し、空きがあれば開始します。

### 操作

| 操作 | 内容 |
|---|---|
| 一時停止（`pause`） | 実行中なら一時停止する。`queued` の行は `paused` にして開始しない |
| 再開（`resume`） | 一時停止中のダウンロードがあれば再開する。無ければ `queued`・`attempts = 0`。導線が無かった行は、作品ごと積み直す |
| やり直す（`retry`） | `queued`・`attempts = 0` |
| 中止（`cancel`） | 取り消して `canceled` |
| 削除（`remove`） | 取り消して行を消す |
| すべて再開 | `paused`・`error`・`canceled` の行に「再開」 |
| すべて一時停止 | `running`・`queued` の行に「一時停止」 |
| 完了・中止を一覧から消す | `done`・`canceled` の行を消す（ファイルは消さない） |
| ダウンロードし直す（`redownload`） | 作品の行（`paused` を除く）を `queued` に戻し、保存先・大きさ・続きの情報・失敗回数を消す。実行中・待機中の行があれば何もしない |

### 一覧に付く実行中の情報

`download:list`・`download:progress` の行には、データベースに無い次の値が付きます。

| 値 | 内容 |
|---|---|
| `bytesPerSec` | 取得中の速さ |
| `preparing` | 準備中・開始待ち |
| `inBatch` | 今回のまとまりに含まれる（何も待っていない・実行していない状態から積んだ行の集まり。起動時は `queued`・`paused` の行） |
| `productBytes` | 作品全体のファイルサイズ |

ダウンロード管理の容量は作品ごとに数え、全行の大きさが分かっていればその合計、分からない行があれば `max(分かっている合計, productBytes)` を使います。

## 後処理

### 判断（ダウンロード完了時）

作品のダウンロードの行に `queued`・`running`・`paused` が無くなったとき、台帳のアーカイブごとに判断します（展開済みのアーカイブは除く）。

| 保存のしかた（[規則](rules.md#保存のしかた)） | 積むジョブ |
|---|---|
| 展開して使う | `post.autoExtract` なら `extract`（`deleteArchive = post.deleteArchiveAfterExtract`） |
| 圧縮のまま持つ | 下の順に判断する |

圧縮のまま持つ作品:

1. PDF を消す: 作品が [PDF を消す対象](rules.md#pdf-を消す対象) ∧ 種別が `post.stripPdfTypes` に含まれる ∧ 7-Zip がある ∧ [消す PDF](rules.md#消す-pdf) がある → `pdf`
2. 種別の扱い（`post.archiveHandling`）が `archive` でなければ、作品を「作り直しの後に展開」の対象にする
3. MP3 だけ残す: `post.lossyOnly` ∧ [消す WAV / FLAC](rules.md#消す-wav--flac) がある ∧ 7-Zip がある → `lossy`（残る WAV の合計が `post.flacMinBytes` 以上で `post.autoFlac` なら `thenFlac`）
4. 上に当たらなければ、`post.autoFlac` ∧ ffmpeg がある ∧ WAV の合計が `post.flacMinBytes` 以上 → `flac`

### 実行

- ジョブは 1 件ずつ、積んだ順に実行します。
- キューが空になるたびに「作り直しの後に展開」の対象の作品を確認し、その作品のジョブが残っていなければ、台帳のアーカイブ（分割の 2 つ目以降を除く）に `extract` を積みます（`deleteArchive` は種別の扱いが `extractDelete` のとき）。

### extract（展開）

1. 空き容量を確認し、作業フォルダに展開する。
2. 中身が 1 つのフォルダだけなら、その中身を展開先の直下に置く。
3. 展開先（アーカイブと同じフォルダ、アーカイブ名のフォルダ）に移し、台帳に `kind = 'folder'`・`source = 'extract'`・`derived_from = アーカイブ` で登録する。
4. 展開したファイル数がアーカイブの一覧以上で、`deleteArchive` ∧（保存のしかたが「展開して使う」∨ `archivedToo`）なら、アーカイブ（分割のすべて）を削除して台帳から外す。

### flac・lossy・pdf（作り直し）

| 段階 | アーカイブ | 展開したフォルダ |
|---|---|---|
| 対象を選ぶ | アーカイブの一覧から | フォルダの中身から |
| 取り出す | 残すファイルだけを作業フォルダへ（`lossy`・`pdf`）/ すべて（`flac`） | — |
| 変換 | WAV を FLAC にして検証（`flac`） | 同左 |
| 作り直す | 音声・画像・動画・アーカイブ・PDF は無圧縮、ほかは圧縮で zip を作る | — |
| 検査 | zip の CRC と、入れたファイルがすべてあるか | — |
| 入れ替え | 元（分割のすべて）を `original` に従って処理し、新しい zip を `<アーカイブ名>.zip` に置いて台帳に登録（`source` = ジョブの種類） | 消すファイルを `original` に従って処理 |

- `original`: `trash` = ごみ箱、`delete` = 削除、`keep` = 元を `<名前> (元).拡張子`（`flac` は `(WAV)`）に改名して残す。
- どの段階で失敗しても、元のファイルは変えません。
- FLAC の検証: 変換前後でサンプル数と音声データのハッシュが一致したものだけを差し替えます。32bit 浮動小数点の WAV・同名の FLAC がある WAV は対象外です。
- `lossy`・`pdf` の選択展開では、UTF-8 のファイル一覧を 7-Zip に渡し、ワイルドカード解釈を無効にします。ZIP の一覧・展開の文字コードは [アーカイブの規則](rules.md) に従います。展開後のファイル数が予定数と異なる場合は、元を置き換える前に停止します。

### move（移動）

保存先・構成の変更に伴う移動（→ [ファイルの操作](#移動)）を 1 件のジョブで順に行います。

## 中身の一覧（見取り図）

`buildContentIndex` が、作品の台帳のファイル・フォルダ・アーカイブを読み、`ContentIndex`（[形](data-model.md#contentindexcontent_cacheindex_json)）を作ります。

- 展開したフォルダがあるアーカイブは、中身をフォルダから並べ、アーカイブからは概要だけを出します。
- ファイルの種類は拡張子で分けます（[規則](rules.md#中身の分類)）。
- 音声はフォルダごとのグループにし、フォルダ名から版のラベルを付けます。

### 作り置き（`ContentCache`）

- 署名 = `v4|<作品の台帳の署名>`。台帳が変わると署名が変わります。
- 要求されたとき、作り置きがあればすぐ返し、署名が違えば裏で作り直して `content:updated` を通知します。
- `content:verify` は、台帳のファイルの有無を開かずに確かめ（`missing_at` を更新）、zip の目次を裏で読みます。

### mylib:// プロトコル

- 台帳にあるパスとその配下だけを返します。ほかは 403。
- `mylib://f/…`: ファイルを Range 対応で返します。
- `mylib://a/…`: アーカイブの中の 1 ファイル。
  - zip を自前で読める場合: 無圧縮のエントリは Range で直接返す。圧縮エントリは、音声・動画でなく Range 指定が無く 64 MB 以下ならその場で展開して返し、それ以外は一時キャッシュに書き出してから返す。
  - 読めない形式（rar・7z・暗号化など）: 7-Zip で一時キャッシュに書き出してから返す。
  - zip の目次が一時的に読めないときは、3 回まで間隔を空けて読み直します。
- 一時キャッシュ（`%TEMP%\Simaeru-cache`）は、合計が 3 GB を超えると最終更新の古いものから消します。
- クエリ文字列は無視します。
- HTML・RTF は `text/plain` で返します。
- すべての応答に `Access-Control-Allow-Origin: *` を付けます（ボイスプレイヤーは `<audio crossOrigin="anonymous">` を Web Audio に通すため。許可が無いと無音になる）。`OPTIONS` には 204 を返します。

## 閲覧

| 画面 | 仕様 |
|---|---|
| 画像ビューア | フォルダごとにページ。見開き（2 ページ）・綴じ方向（`manga` は右綴じが既定、種別ごとに保存）・一覧。前回のページを `player.state.<productRef>` に保存。前後のページを先読み |
| 表示の大きさ | 合わせ方 = 全体 / 幅合わせ / 原寸（1 画像ピクセル = 1 デバイスピクセル）。倍率 10〜800%（1.25 倍刻み）。原寸か倍率 ≠ 100% のときは画像の大きさを計算して配置し、はみ出したらスクロールとドラッグで移動 |
| ページ送りの間隔 | ホイールの連続回転とキーの押し続け（`repeat`）は、`pageInterval`（0 / 120 / 250 / 450 / 800 ミリ秒）より短い間隔でページを変えない。ホイールは移動量の合計が 60 を超えたら 1 ページ |
| シャープ化 | 表示の大きさにした後に 3×3 ラプラシアン（中央 `1+4k`、上下左右 `-k`、`k` = 0.15 / 0.3 / 0.6） |
| 補間 | バイキュービック（標準）/ ニアレストネイバー（表示倍率 × デバイスピクセル比 > 1 のときだけ） |
| 画像の読み込み失敗 | 400・800・1200 ミリ秒後に読み直し（3 回）、その後「もう一度読み込む」。1.5 秒以上かかると読み込み中を表示 |
| ボイスプレイヤー | グループ（フォルダ）ごとに再生。版の切り替えは再生位置を保つ。台本（PDF・テキスト）・字幕（lrc / srt / vtt）・画像のタブ。繰り返し（なし・グループ・1 曲）・速さ・音量。聴いた位置を保存 |
| PDF | ページを縦に並べ、表示範囲の前後 600px に入ったページだけを描画。倍率 50〜300%（25% 刻み） |
| テキスト | 文字コードを BOM → UTF-8 → Shift_JIS の順に判定。HTML・RTF は文字だけを表示 |
| 閲覧日時 | ボイスプレイヤー・ビューアを開いたとき、既定のアプリや NeeView で開いたとき、ストリーミングの導線を開いたときに `viewed_at` を更新 |

### アプリ内ブラウザ（`browser:open`）

- 開けるのは、その作品の `links` の URL と `detail_url` だけです。
- `stream`・`play` の導線はアプリ内ブラウザで開きます。`external` 指定のときと、`download`・`page` は既定のブラウザで開きます。
- `floor_id = 'video'` の `stream` は、公式の HTML5 プレイヤーのページで、**既定のブラウザで開きます**（アプリ内ブラウザでは DRM のエラーになるため）。URL の `part=<n>/` が続いているときは最後の 1 つにして開きます。
- セッションはサイトのパーティション（`site_id = 'dlsite'` は DLsite、ほかは DMM）です。
- http(s) 以外への移動と、http(s) 以外の新しいウィンドウは開きません。ただし `dmm` で始まる形式（公式アプリを起動するリンク。DMM プレイヤーでのダウンロードなど）は、ページから移ろうとしたときに Windows に渡します。http(s) の新しいウィンドウは、同じセッションのアプリ内ブラウザで開きます。
- UserAgent から `Electron/…` とアプリ名の部分を除きます。
- キー: `F5`・`Ctrl+R` 再読み込み、`Alt+←/→` 戻る・進む、`F11` 全画面、`Esc` 全画面を終える、`Ctrl+W` 閉じる。

### DMM Player（`viewer:openDmmPlayer`）

- 開けるのは、その作品の台帳にある `.dcv`・`.dmmmp4` のファイルだけです。
- DMM Player の場所: `HKCR\.dcv` の既定値（ProgID）→ `HKCR\<ProgID>\shell\open\command` の実行ファイル。無ければ `%LOCALAPPDATA%\Programs\DMM Player v2\DMM Player v2.exe`。どちらも無ければ入っていない扱いです（`install:dmmPlayerStatus`）。
- 実行ファイルにファイルのパスを渡して起動し、`viewed_at` を更新します。復号はしません。

### NeeView

- 「開く」を NeeView に渡します（`NeeView.exe <パス>`）。
- アプリから取得した NeeView（ZIP 版、`NeeView.settings.json` の `UseLocalApplicationData = false`）の設定ファイルは `Profile\UserSetting.json` です。
- 取得時、設定ファイルが無ければ次の内容で作ります（`Format` は `NeeView.exe` の FileVersion の上 3 つ）。

  ```json
  {
    "Format": "NeeView/<major>.<minor>.<build>",
    "Config": {
      "System": { "Language": "<画面の言語>" },
      "BookSetting": { "PageMode": "WidePage", "IsRecursiveFolder": true },
      "BookSettingDefault": { "PageMode": "WidePage", "IsRecursiveFolder": true }
    }
  }
  ```

- `tools:neeviewDefaults` は、既存の設定ファイルの `BookSetting`・`BookSettingDefault` の `PageMode`・`IsRecursiveFolder` だけを書き換えます。
- NeeView の起動中は、取得・書き換えを行いません。取り直すときは `Profile` を引き継ぎます。
- 書き込みは 2 字下げ・CRLF・BOM なしです。

## インストールと起動

### インストールの判定

展開したフォルダの中身から型を判定し（[規則](rules.md#インストールの型)）、画面で方法を選びます。

| 方法 | 結果 |
|---|---|
| このフォルダをそのまま使う / ▶ 起動 | `kind = 'managed'`、起動ファイルを紐付け |
| インストーラを実行 | インストーラを起動するだけ。導入先はあとで選ぶ |
| 導入先のフォルダを選ぶ | `kind = 'managed'` |
| 導入済みプログラムと紐付ける | `kind = 'linked_existing'`、`uninstall_key` にレジストリのキー |
| DMM GAMES PLAYER のゲームと紐付ける | `kind = 'dmm_game_player'`、`uninstall_key = dgp:<gameType>:<productId>` |

導入済みプログラムの一覧は、レジストリの Uninstall キー（HKLM・HKCU、32/64bit）から表示名・発行元・導入先・アイコン・版を読みます（1 分間キャッシュ）。

### 起動（`install:launch`）

| `kind` | 起動 |
|---|---|
| `dmm_game_player` | DMM GAMES PLAYER が入っていて、`dmmgame.cnf` にそのゲームがあれば `dmmgameplayer://play/<gameType>/<productId>/<cl\|main>/win` を開く（`gameType` が `GCL`・`ACL` なら `cl`、`GMAIN`・`AMAIN` なら `main`）。無ければエラー |
| そのほか | 起動ファイルが無ければエラー。`.exe` は作業フォルダを exe の場所にして起動（起動できなければシェルで開く）。ほかは既定のアプリで開く |

起動に成功したら `last_launched_at` を更新します。

### DMM GAMES PLAYER

- 専用の作品: タグに `DMM GAMES PLAYER専用` を含む作品。
- 検出: レジストリの `dmmgameplayer` プロトコルの登録から実行ファイルを求め、存在を確認します。
- ゲームの一覧: `%APPDATA%\dmmgameplayer5\dmmgame.cnf` を読みます（書き換えません）。
- `install:dgpSummary`: 入っているか・実行ファイル・専用の作品の数・そのうち `installed` の数。

### 紐付け候補

- 対象: `installed` でない作品のうち、ゲーム・ツール、またはタグに `DMM GAMES PLAYER専用` を含む作品。
- 専用の作品: DMM GAMES PLAYER のゲームを[近さ](rules.md#dmm-games-player-のゲームの近さ)で並べ、最も近いものが 0.4 以上なら候補にします。
- そのほか: 導入済みプログラムを[近さ](rules.md#導入済みプログラムの近さ)で並べ、最も近いものが 0.6 以上なら候補にします。
- ほかの作品の `installed` の紐付けに使われている相手（`uninstall_key`）は除きます。
- 結果を `products.link_candidate` に書きます（候補が無ければ NULL）。自動では紐付けません。
- 検出するとき: 起動の 20 秒後、同期のあと、「最新にする」、紐付けを外したとき、`install:refreshCandidates`。
- 検出の前に、[リンク切れ](#リンク切れ)を見回ります。

### リンク切れ

`installations.state` が `installed`・`broken` の作品について、紐付けが生きているかを確かめ、`installed` と `broken` を付け直します。

| 紐付け | 生きている条件 |
|---|---|
| `dmm_game_player` | DMM GAMES PLAYER の設定ファイルに `uninstall_key` と同じゲームがあり、入っている。設定ファイルが無ければ切れている。読めなければ判断しない |
| そのほか | `executable_path`（無ければ `install_path`）がある |

- 見回るとき: 紐付け候補を検出するとき、詳細の「インストール・起動」を表示したとき（`install:checkLink`）、起動に失敗したとき。
- 変わったら `library:changed` を通知します。
- `broken` の作品は、紐付け候補を探す対象に入ります。紐付けを外すか、紐付け直すと `broken` でなくなります。

## 総集編・セットの収録作品

総集編・詰め合わせ・セット商品に収録された作品を、同じサイトの同じサークル・ブランドの作品（未購入を含む）から探し、単独で持っているかを示します。

### 組み立て（`buildCompilations`）

すべての作品について、次の順に判断します。

`compilation.guess` が `'1'` でないときは、次のどちらかに当たる作品だけを対象にします（推定しなくても分かるもの）。

- `product_type = 'set'` で、中身（`parent_product_id`）の行がある
- `site_id = 'dmm'` ∧ `floor_id = 'dlsoft'`（PCゲーム）

設定を変えたら、すぐに組み立て直して `library:changed`（`null`）を通知します（`library:setCompilationGuess`）。

1. `product_type = 'set'` で、同じサイト・区分に `parent_product_id` がこの作品の行があれば、それらを収録作品にする（作品 ID で結び付く）。
2. 説明文があり、[総集編らしい](rules.md#総集編らしさ)なら、説明文から[収録作品を読み取る](rules.md#収録作品の読み取り)。
3. 照らし合わせる相手を集める。
   - [作品一覧を取るストア](rules.md#作品一覧を取るストア)があれば、その作り置きの一覧（`store_catalog`）。
   - 同じサイトの手元の作品のうち、同じサークル（`maker_id` が同じ。無ければ `maker` が同じ）のもの。
   - 総集編自身（作品 ID が同じもの）は除く。
4. [照らし合わせる](rules.md#収録作品の照らし合わせ)。照らし合わせた結果が 2 つ以上なら、`compilation_entries` に書く。
5. 作品一覧が無い、または古い（最後に取ってから 14 日。失敗していたら 1 日）なら、取りに行く対象に入れる。

書く前に `compilation_entries` のすべての行を消します。`compilation_overrides` は残します。

- 組み立て直すとき: 起動の 30 秒後、同期のあと（1 秒後）、詳細を取得したあと（5 秒まとめる）、「最新にする」、作品一覧を取ったあと。実行中に頼まれたら、終わったあとにもう一度実行します。
- 組み立てたら `library:compilationsChanged` を通知し、取りに行く対象の作品一覧を 1 つずつ（1 回に 40 件まで）取ります。1 つでも取れたら、もう一度組み立てます。

### 作品一覧の取得（`fetchMakerCatalog`）

- ストアの公開の作品一覧のページを 1 ページ目から読み、新しい作品が出てこなくなったページ、2 ページ目以降で HTTP 404 のページ、20 ページ目で終えます。ページの間は 600 ミリ秒空けます。
- 取れたら `store_catalog` を入れ替え、`store_catalog_makers` に日時と件数を書きます。失敗したら、前の一覧を残して `error` と日時だけ書きます。
- セッションは、DMM は DMM のパーティション、DLsite は DLsite のパーティションです。ログインは要りません。
- `library:refreshCatalog` で、その総集編の作品一覧をすぐに取り直します。

### 持っているか（`library:compilation`）

収録作品ごとに、見つけた作品（`compilation_overrides` があればそちら）について次を返します。

| 項目 | 内容 |
|---|---|
| `owned` | 同じサイトで `product_id` または `content_id` が同じ作品（総集編自身を除く）。`parent_product_id` が NULL の行を優先 |
| `ownedVia` | `owned` の `parent_product_id` が NULL なら `single`（単独で購入済み）、あれば `set`（セットの中身として所持）、`owned` が無ければ NULL（単独では未購入） |
| `alsoIn` | 同じ作品 ID を収録作品に持つ、ほかの総集編・セット |

- `containedIn`: その作品の `product_id`・`content_id` を収録作品に持つ総集編・セット（自身を除く）。
- `catalog`: 作品一覧を取るストアと、`store_catalog_makers` の記録。ストアが無ければ NULL。

### 手で直す（`library:setCompilationOverride`）

| 操作 | 内容 |
|---|---|
| `set` | 候補から選んだ作品にする（候補に無い作品 ID は断る） |
| `none` | 外す（`matches = []`） |
| `clear` | 手で直した行を消す（自動に戻す） |

選び直す候補（`library:compilationCandidates`）は、作品一覧と、同じサイトの手元の同じサークルの作品（総集編自身を除く）を[タイトルの近さ](rules.md#収録作品の照らし合わせ)で並べ、0.2 以上の上位 10 件です。持っているか（`owned`）を付けます。

収録作品のストアのページ（`library:openCompilationItem`）は、その総集編の見つけた作品の URL だけを既定のブラウザで開きます。

### 検索

検索対象にタイトルを含むとき、検索語が収録作品のタイトル、または見つけた作品（手で直したものを含む）の JSON に含まれる総集編・セットも結果に入れます（`LIKE`）。

## ファイルの操作

### 削除（`library:trashFiles`・`library:trashMany`）

1. 作品に `running`・`queued` のダウンロード、または `running`・`queued` のジョブがあれば断る。
2. 対象（指定したファイル、または作品の台帳のすべて）をごみ箱へ入れる。ごみ箱へ入れられず実体が残っているものは、失敗として返す。実体が無いものは台帳から外すだけ。
3. ごみ箱へ入れたパスを台帳から外し、その配下の台帳の行も外す。
4. `installation.install_path` がごみ箱へ入れたパスの配下なら、紐付けを外す。
5. 作品の台帳に実体が残っていなければ、`done` のダウンロードの行を消す。
6. `library:filesChanged` と `library:changed` を通知する。

`library:trashPlan` は、作品数・ファイル数・大きさ・処理中で外す作品数・インストール先も消える作品数を返します。

### 移動

- 計画（`download:relocationPlan`）: 以前の保存先（`download.rootHistory`・既定の保存先を含む）の中にある台帳のファイルのうち、今の保存先・構成での置き場所と違うものを挙げます。ダウンロード中のものは除きます。
- 実行: 同じドライブは名前の変更。別のドライブは作業用の名前で複製し、中身（ファイル数と大きさ）を照らし合わせてから本来の名前にして、元を消します。
- 台帳の `path`・`derived_from`、ダウンロードの `save_path`、インストールの `install_path`・`executable_path` を付け替え、空になったフォルダを消します。

### 取り込み

- 設定 `import.folders`（既定は保存先）を走査し、台帳に無いファイル・フォルダを挙げます（読むだけ）。
- 名前から作品 ID とタイトルを取り出し、購入履歴（作品 ID・コンテンツ ID・タイトル）と照合します。

  | 照合 | 確度 | 扱い |
  |---|---|---|
  | 作品 ID が 1 作品に一致 | `id` | 自動で台帳に登録（`source = 'scan'`） |
  | 作品 ID が複数の作品に一致 | `id` | 画面で選ぶ |
  | 作品 ID は取れたが購入履歴に無い | — | 候補なし |
  | タイトルが一致 | `high` | 画面で選ぶ |
  | タイトルが部分一致・省略形で一致 | `medium` | 画面で選ぶ |

### 最新にする（`library:refreshLocal`）

1. 台帳のフォルダの配下にある、個別の台帳の行を外す。
2. 保存先を走査して取り込む。
3. すべての作品の見取り図を作り直す。
4. 紐付け候補を検出し直す。
5. 総集編・セットの収録作品を組み立て直す。
6. `library:filesChanged`（`null`）を通知する。

## 外部ツールの取得

| ツール | 配布元 | 取り出すもの |
|---|---|---|
| 7-Zip | GitHub `ip7z/7zip` の最新リリース | `7zr.exe` とインストーラ（`7z*-x64.exe`）を取得し、インストーラから `7z.exe`・`7z.dll` を取り出す |
| ffmpeg | GitHub `BtbN/FFmpeg-Builds` の latest（`win64-lgpl-shared`） | `bin` の中身（`ffmpeg.exe`・`ffprobe.exe`・DLL）とライセンス |
| NeeView | GitHub `neelabo/NeeView` の最新リリース | `NeeView<版>.zip` の中身 |

1. リリースの情報を取得し、配布物を選ぶ。`digest`（sha256）が無い配布物は取得しない。
2. 取得して sha256 を照合する。
3. `tools\<名前>.installing` に展開し、必要なファイルがあるか確かめる。
4. `installed.json`（`tool`・`version`・`source`・`sha256`・`installedAt`）を書き、`tools\<名前>` と入れ替える。

ツールの場所は、設定で指定した場所 → アプリが取得したもの → PC に入っているもの の順に探します。

## ID とパスワード

- 暗号化は Electron の `safeStorage`（Windows では DPAPI）。使えない環境では保存しません。
- 保存時はデータベースと `credentials.dpapi` の両方に書き、読み戻して一致を確かめます。
- ログインウィンドウで、ID とパスワードの入力欄に値を入れます（送信はしません）。

## データベースの開き方

1. `library.db` を開く（使用中なら 10 秒まで待つ）。`journal_mode = WAL`。
2. `PRAGMA quick_check(1)` が `ok` でない、または `SQLITE_CORRUPT`・`SQLITE_NOTADB` のエラーのときは、破損として次へ。ほかのエラーは起動を止める。
3. 破損: `library.db`・`-wal`・`-shm` を `library.db.corrupt-<日時>` に改名し、新しいデータベースを作って移行する。
4. 退避したデータベースを ATTACH し、`products`・`installations`・`sync_runs`・`settings`・`credentials`・`downloads`・`local_files`・`jobs`・`compilation_overrides` の、両方にある列を写す。表ごとにまとめて写し、失敗した表は 1 行ずつ写す。`content_cache`・`compilation_entries`・`store_catalog`・`store_catalog_makers` と全文検索の索引は写さない（索引はトリガーで作られる）。
5. 移行（`user_version` から `MIGRATIONS` の長さまで）を 1 版ずつトランザクションで適用する。
6. 終了時は `wal_checkpoint(TRUNCATE)` の後に閉じる。

## 多言語化

- 言語: `ja`（日本語）・`en`（English）・`zh`（简体中文）。
- 文言は日本語をキーにして `t(文言, 差し込み)` で表示します。辞書（`en.ts`・`zh.ts`）に無い文言は日本語のまま表示します。
- 差し込みは `{名前}`。値が `false`・`null`・`undefined` なら空文字、渡していない名前はそのまま残します。
- 日付・数値の書式: `ja-JP`・`en-US`・`zh-CN`。
- 言語は起動時にメインプロセスが決め、preload が同期で画面に渡します。言語を変えると画面を読み直します。
- データベースに保存する表示名（導線のラベル、区分・種別・版のラベル、役割名）は日本語のまま保存し、表示時に翻訳します。
- ライセンス表示は、`ja` で `THIRD_PARTY_NOTICES.md`、それ以外で `THIRD_PARTY_NOTICES.en.md`。
